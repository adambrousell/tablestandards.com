01 · Executive Summary

The Problem We Are Solving

At River Pointe Inn, the gap between a dish leaving the kitchen and the correct cutlery being present at the table is managed entirely by institutional memory, manual floor checks, and reactive scrambling at the polish station. There is no system. There is no signal. There is only experience — and when service accelerates, experience is not enough.

"The polish station should never be guessing. It should be executing a ranked work order generated by the tickets on the floor."

— Operational Design Principle

This proposal outlines a full-stack Cutlery Intelligence System — a purpose-built operational platform that connects every dish sold through Toast POS to a live demand calculation, monitors physical bin inventory through a sensor network, and generates a prioritized work order for the polish station in real time. The General Manager sees the entire floor. The polish staff sees exactly what to do next.

No system like this exists as a commercial product. This is built from scratch, owned entirely by River Pointe, and designed to scale.

Every sensor type — weight, RFID, infrared, camera, QR — posts to a single Cloudflare Worker endpoint. No sensor ever communicates with the database directly. The Worker normalizes all input, runs the demand calculation, and writes the result. This architecture means adding a new sensor type in the future is a matter of minutes, not weeks.

04 · Sensor Layer

The Physical Intelligence Network

Each sensor type is deployed where it produces the highest signal. No location is instrumented for its own sake. Every sensor posts to the same endpoint.

⚖
Load Cells
Mounted under cutlery bins. Weight converts to piece count using per-piece gram profiles. Catches quantity changes passively — no staff interaction required.
📡
RFID
High-value individual items — crystal stems, silver serving pieces — carry industrial-grade waterproof tags rated for commercial dishwasher cycles.
〰
IR Beams
Doorways between kitchen, FOH, and dish pit. Every item crossing a threshold is counted. Catches movement that bins don't see.
📷
Camera / CV
Dish pit exit and polish station entry. Visual object counting verifies sensor readings. Phase 2 full CV identifies cutlery by silhouette.
⬛
QR Codes
Every bin carries a QR label. Staff scan to confirm destination when moving batches. Triggers an event identical to any sensor — same pipeline, same audit log.
📻
VoxIntel RF
Passive radio monitoring correlated with staff location and item movement. Surfaces patterns invisible to fixed sensors. Phase 2 integration.

One important hardware note: RFID tags specified for this system are rated for repeated high-temperature commercial dishwasher cycles. Epoxy-encased UHF Gen2 tags from manufacturers such as Xerafy and Confidex are designed for exactly this environment. Tags are applied to bins and racks — not individual pieces of cutlery — which dramatically reduces tag count and unit cost.

05 · Priority Algorithm

How the Queue Is Ranked

The polish queue is not a simple list of what is empty. It is a scored, ranked work order calculated from three independent signals — how short the bin is, how soon the pieces are needed, and how depleted the bin is relative to its par. Every item in the queue has a score. The highest score gets polished next.

Priority = (Deficit × 10) + (60 ÷ Minutes Until Needed × 20) + (Depletion % × 15)
Deficit — pieces short of demand
Minutes Until Needed — from open ticket timing
Depletion % — (par − current) ÷ par
≥ 60 pts — CRITICAL · red
≥ 35 pts — HIGH · amber
< 35 pts — NORMAL / LOW

The queue recalculates every two minutes via a Cloudflare Cron Trigger during service hours. As tickets open, close, and evolve — and as sensors report bin changes — the ranking shifts automatically. Staff at the polish station never need to assess urgency themselves. The system has already done it.

06 · Implementation

Phased Deployment Plan

I
Data Foundation & Software Stack
Week 1 – 2
All software is built and deployed before a single sensor ships. The system is operational on QR scans and manual input while sensor hardware is procured.
  • Airtable base — all 8 tables built and seeded
  • Menu-Cutlery Matrix populated for current menu
  • Cloudflare Worker deployed and connected to Toast webhook
  • GM Dashboard live on Cloudflare Pages
  • Polish Station tablet view deployed
  • QR labels printed and affixed to all bins
II
Sensor Hardware Installation
Week 3 – 5
Physical sensors installed station by station. Each goes live and begins posting to the existing Worker endpoint the moment it is mounted.
  • Load cells under bins at Kitchen Pass and Side Stations
  • IR break-beams at kitchen-FOH and dish pit thresholds
  • RFID readers at Bar and Storage
  • Industrial RFID tags affixed to bins and racks
  • Baseline calibration — weight profiles per piece type
III
Calibration & Staff Integration
Week 6
One week of tuning with live service data. Staff are introduced to the polish station tablet with no training beyond "look at this list and do number one first."
  • Priority algorithm tuned to actual River Pointe service cadence
  • Table-to-station mapping confirmed against floor plan
  • Par levels adjusted from observed baseline
  • Polish station tablet mounted and running
IV
Camera CV & VoxIntel Integration
Month 2 – 3
Advanced sensing layers added once clean baseline data exists. Camera vision verifies sensor counts. VoxIntel surfaces movement patterns invisible to fixed sensors.
  • Camera feeds at dish pit exit and polish station entry
  • Frame-differential object counting — no cloud processing required
  • VoxIntel passive RF pipeline integrated
  • Loss detection statistical baseline established
